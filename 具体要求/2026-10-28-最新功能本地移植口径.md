# 最新功能本地移植口径

这次是按用户要求把上游最新功能移植成本地演示版，不重新设计财务口径。对应上游版本为 `2edcc89ac2a30a6e6a289313d410fdfc09cd87de`（2026-10-21）。

保留 React 界面、五个虚构身份和本地 SQLite 架构。全部预置数据继续虚构；不读取原业务数据库、原始模板、截图或历史文档。只在环回地址运行，不部署本轮更新到公网。

## 从上游迁入的规则

- 新收款只分配到合同，不指定某次发货，也不要求手动选择预付款、尾款或全款。旧货款类型和旧发货引用保留兼容；新页面按累计金额计算进度。
- 新建收款的合同分配以到账日生效。修改整笔收款时，已有分配保留其生效日；如果原生效日等于原到账日，随更正后的到账日调整。后来增加的合同分配按上海时区当天生效，避免把新分配错误回溯到老水单日期。
- 预付款按合同金额乘约定比例、累计合同分配计算首次达标日。默认比例为 30%，0% 且已形成合同金额时使用合同日期。尚无联系单、金额未形成时不生成达标日或自动交期。
- 准备中的发货安排可以整单原子编辑或删除；实际发货前检查物料号。已确认实际发货的事实通过“作废并复制”更正，旧事实保留，已开票时先撤销开票。
- 收款在合同内按发货先后抵扣；合同预付款进度、客户到账余额和已确认利润仍是不同口径。利润继续基于实际开票月份、成本及汇率计算，不以到账直接替代利润。
- 包装车间保存在包装版本上，已有版本的模板不能直接换车间。复制联系单采用当前可用的已确认包装版本并提示升级；原单仍保留原版本。
- 美金实际开票、预计开票按发货记录**创建日期**筛选，使用所选月份汇率和发货明细快照单价。同一物理发货的开票关联不完整或金额不一致时拒绝导出。

## 本地兼容处理

- 旧演示种子中预付款比例 `40` 是百分数，新版使用比例 `0.4`。迁移只转换单位，40% 的经济含义不变；已使用 0–1 的合同保持原值。
- SQLite 结构版本为 3。升级前自动用 SQLite Backup API 保存完整快照，再在事务中回填生效日、车间和旧发货表头。失败回滚，重启不会重复迁移。
- 旧版单独发货补建一对一物理表头，保留原子记录 ID、单号、发货日期、金额及发票关联，让新版编辑、确认、作废复制入口能够使用。单号碰撞时只给新表头附加 LOCAL 后缀。
- 收款导出按整笔到账列示，包含未分配预存款及合同分配说明，避免丢掉零分配水单或重复累计到账金额。
- 导出沿用代码生成的通用虚构版式。预计开票的财务成本留空，利润列保留填写成本后的 Excel 计算公式；它不进入系统已确认利润。
- 移除 APS 同步按钮、自动跟踪开关、同步任务及远程控制接口。`aps_scheduled_date` 仅作为旧字段名兼容手工排产日期，`aps_auto_query_enabled` 固定为 false。放行申请中依赖 APS 的制造周期等信息留空供手填。
- 汇率手动维护、QA/排产日期手动填写；导出从本机生成。Telegram 密钥仍仅在本地配置，实际发送仍需手动确认。
- 公网演示不在本轮发布范围；保持既有十类静态样例。新增放行申请、美金实际开票和预计开票只在本地即时生成。
