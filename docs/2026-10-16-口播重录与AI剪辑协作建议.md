# 个人订单驾驶舱：口播重录与 AI 剪辑协作建议

调研日期：2026-10-16。此次交付是工作流建议与交接说明，没有录制、剪辑或发布视频，没有连接 Claude、GitHub 集成或业务系统。

## 推荐怎么配合

推荐采用「AI 先设计镜头 → 人录口播 → 按镜头表录屏 → AI 补图形与剪辑 → 人看完整片」的方式。

不必一开始就在“全部自动录”和“自己全部录好”之间二选一。先让 AI 了解产品，指出需要什么画面，再录素材，能够减少补录。你的经验、判断和表达是主线；真实软件操作负责证明功能；关键词、图形和 B-roll 帮助观众理解。

| 方案 | 适合的情况 | 这次的建议 |
| --- | --- | --- |
| 你录口播与主要操作，AI 规划、补素材和剪辑 | 第一人称介绍、自然讲解、需要保留个人表达 | 首选，录制前先拿到镜头表 |
| 你录口播，AI 自动操作软件并录屏 | 镜头路径稳定、需要反复补录页面 | 适合首页、图表、筛选等短镜头，先试一段 |
| AI 包办旁白、界面、录屏和剪辑 | 标准化宣传片或无真人演示 | 这次不优先，容易冲淡个人经验与现场感 |

## GitHub、代码和网站分别解决什么

本地 Claude Code 可以在普通文件夹启动，不要求把 GitHub 账号连接给 Claude。给本地代码与资料文件夹即可开始。Claude Code 网页云端任务使用 GitHub 仓库是另一种模式，不必为了本地视频制作选择它。[官方本地启动说明](https://code.claude.com/docs/en/quickstart)、[网页云端任务说明](https://support.claude.com/en/articles/12618689-claude-code-on-the-web)。

网站帮助它理解观众实际看到的界面；代码帮助它核对功能和业务规则；口播与素材让它知道这支视频真正要讲什么。只有仓库和链接，缺少受众、核心观点、录制素材与风格参考，仍然不够。

可以分两步交材料：

1. **先做分镜**：本项目 README、`docs/2026-09-29-初录口播精简稿.md`、`docs/个人订单驾驶舱-介绍视频脚本.md`、经人工挑选的当前演示截图，以及有需要时的公开演示网址。
2. **再做素材和成片**：新的口播视频或音频、按编号录的屏幕片段、你选的风格参考。只有需要核对代码或运行本地写入演示时，再提供相关源码、依赖清单与虚构种子。

资料放在独立制作目录，保留原素材；新工程、代理文件、预览与成片另存。无需整份复制 `.git`、历史工作记录、个人配置、数据库、备份或 `node_modules`。不向第三方提供环境文件、密钥、生产资料或原业务系统素材。这个做法用于最小授权和减少无关信息，不能承诺匿名或规避服务地区规则。

本地执行也不等于离线模型：Claude Code 会把进入上下文的内容通过网络发送给模型服务。应检查实际使用的产品与数据设置。[官方数据流说明](https://code.claude.com/docs/en/data-usage)。

## 账号地区问题怎么理解

截至调研日，Anthropic 的支持地区政策列出的地区不含中国大陆；政策涉及个人实际使用所在地，以及实体注册、总部、所有权或控制关系。不能据此推导“中国国籍个人在任何地方使用都必然被封”。[官方支持地区政策](https://www.anthropic.com/legal/supported-regions)。

官方说明会使用 IP 与其他信号判断国家或地区，以执行条款和防滥用，这部分不能关闭。没有查到“连接了显示中国身份的 GitHub 就直接封号”的公开规则；也不能保证不连接 GitHub、只给代码就不会触发限制。若实际所在地不受支持，应选择当地可正式使用的工具，或向官方核实资格；不把更换网络、付款资料或隐藏身份当作可靠解决办法。[官方位置数据说明](https://privacy.claude.com/en/articles/11186740-does-claude-use-my-location)。

这套制作方法可以交给其他具备本地文件、脚本和视频工具能力的助手。把旁白、镜头表、时间线和素材留在自己本地，可降低对单一账号的依赖。

## 截图、自动录屏与剪辑的能力边界

Claude Code 官方浏览器集成支持 Microsoft Edge，可以操作网页、保存截图和录制交互 GIF；需要安装扩展、满足对应订阅及登录条件。项目只能使用 Edge，不能照搬示例启动 Chrome。浏览器扩展录 GIF 不等于完成一支带真人旁白的正式视频。[官方浏览器集成说明](https://code.claude.com/docs/en/chrome)。

如需自动生成视频素材，可以让助手编写 Playwright 操作脚本并录制，明确使用 `channel: 'msedge'`。录制默认并未开启，分辨率也需要明确配置；应先检查一段样片的清晰度、停留、鼠标表现和动作时序。[Playwright 的 Edge 支持](https://playwright.dev/docs/browsers#google-chrome--microsoft-edge)、[视频录制说明](https://playwright.dev/docs/videos)。

正式录制可以使用 OBS 等录屏工具，助手负责镜头动作与节奏；后期可用 FFmpeg 处理裁切、音频与编码，用代码动画工具制作关键词、连线、流程图和局部强调。这里是制作路线建议，不表示已经安装或验证了这些工具。Remotion 等渲染器也要先核实浏览器配置，不能无意启动 Chrome。

“AI 生成 B-roll”要分开看：流程图、关键词、表格汇聚等可以用代码制作；写实场景视频通常需要单独的视频生成服务、素材来源与相应授权或费用。产品界面和功能效果优先使用本项目真实演示录屏，示意图明确标注，不把生成画面当作真实操作证据。

## 这一版可以怎么讲、怎么演

产品名称沿用仓库正式名称“个人订单驾驶舱”。下面是镜头方向，不是已经确定的片长或新版逐字稿。旧精简稿标注约 7—9 分钟，新片时长应按本次内容另定。

| 口播要说明什么 | 主要画面 | 可配的辅助元素 |
| --- | --- | --- |
| 同一笔订单在多张表之间反复整理 | 你出镜，或纯虚构的表格示意 | “重复录入”“到处找数据”；几张表汇成一条链 |
| 我把这些具体问题做成了一个工具 | 产品首页，清楚出现名称 | 合同 → 生产跟进 → 发货 → 收款 → 利润 |
| 今天该先跟进什么 | 首页概况和今日优先事项 | 一次强调一张卡片，保留读数时间 |
| 一笔订单怎么追下去 | 同一虚构客户、合同及关联联系单 | 放大进度、鼠标指向、关联编号 |
| 钱和利润为什么不能只看一个数字 | 货款平衡、利润状态与缺项提示 | 规则关键词；示例金额与实际画面一致 |
| 数据积累以后能帮我判断什么 | 客户价值矩阵、客户产品分析 | 先指出一个象限或产品，再给解释 |
| AI 怎样帮我把工作经验做成工具 | 回到你本人或首页 | “业务经验”“清楚的问题”“可用的工具” |

不要为了介绍全面逐个点完所有菜单。优先用一个完整案例，再给一个有记忆点的分析镜头。旁白说到什么，就给那个对象足够大的画面；手机观看版本不要长期塞满整张桌面表格。

项目现有规则继续有效：公网只读，可以浏览、切换演示身份、预览汇报及下载样例报表；新增、编辑、生成写入结果使用本地虚构种子重建的版本，并只在环回地址运行。Telegram 只录预览。所有客户、公司和业务数据均为虚构。

利润按既有开票、成本与汇率条件讲解；客户货款平衡不直接说成逾期欠款；未发货也不能推断尚未生产。画面美化不能改变业务含义。

## 建议的实际制作顺序

1. 先确定观众和一句主张，例如“做外贸的人，怎么把自己每天重复整理的业务变成一个工具”。让 AI 交付讲述大纲和镜头表，每行包含旁白、页面、操作、重点和所需素材。
2. 挑出一个完整的虚构案例，核对合同、联系单、发货与收款之间的关联；提前选择有数据的分析时间范围。先走一遍操作，不急着正式录。
3. 分段录口播，保留自然语气。每段主要表达一个意思，讲错时停一下重讲。需要真人出镜时保留原始视频与干净人声。
4. 按镜头表录屏，每段只做一组动作。建议每段约 10—25 秒，前后各留约 2 秒供剪辑；画面太密时提高源录制分辨率，为后期放大留余地。声音和操作可以分开录，不必强求同步。
5. 先按真实口播转写、选取与粗剪，再以保留下来的旁白时间码对齐录屏。先完成一小段约 20—30 秒的样片，检验字号、比例、节奏和图形风格，再扩展全片。
6. 配关键词、图形和 B-roll，保留可修改时间线。字幕与关键图形不互相遮挡，音乐不压人声，不为了删除语气词剪断句意。
7. 交付可播放预览、字幕、素材清单和可继续编辑的源工程。工具检查要说明范围；最后人工完整看、听一遍，核对数值、操作结果与声画同步。

> 我要重新制作“个人订单驾驶舱”的第一人称中文介绍视频，形式是我的真实口播，配合软件演示、关键词、图形和少量 B-roll。请先担任导演和演示教练。
>
> 先读我提供的 README、旧口播稿、旧分镜和截图；如具备浏览器能力，再用 Microsoft Edge 查看我授权的虚构演示站。区分已经实际查看的页面与只从文档得知的功能，列出当前可用的录屏、转写、动画和剪辑工具。不要声称已经具备未验证的能力。
>
> 先给我推荐的讲述主线、需要补充的少量关键问题，以及“旁白段落—页面和操作—画面重点—录制方法—辅助图形”的镜头表。告诉我哪段我录更合适，哪段可以由你自动补录。不要在只收到网站链接时自行决定整支片子的内容。
>
> 我倾向先录自然口播，再按镜头表单独录屏。后续请根据真实素材的时间码剪辑，并先完成约 20—30 秒样片检验风格，再扩展。最终需要可播放视频、字幕和可编辑工程；具体比例、时长与风格以我们后续确定的方案为准。
>
> 本地素材放在独立制作目录，原文件保留。无需连接我的 GitHub，也不提交或推送项目；网站代码仅用于理解和核对，视频输出另存。若复制项目规则，先向我指出其中与这个独立制作任务冲突的发布指令。
>
> 只使用本演示项目的虚构客户和数据。公网只读；写入操作必须使用本地由虚构种子生成的版本且仅在环回地址运行；Telegram 只展示汇报预览。不得读取环境文件、真实数据库、备份、生产资料或原项目，不改变金额、利润、回款与状态规则。所有网页操作和验证只用 Edge，禁止启动 Chrome；渲染工具同样先核对浏览器要求。

## 交接时记住

不要只告诉助手“帮我剪得高级一点”。让它具体说明每个镜头要让观众看懂什么、素材从哪里来、什么时候出现、停多久，以及最终交付什么可修改文件。导演方案先解决讲什么和怎么证明，动效再解决怎样更容易看懂。
