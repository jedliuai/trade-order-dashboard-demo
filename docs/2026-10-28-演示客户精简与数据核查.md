# 演示客户精简与数据核查

## 演示数据

本地默认种子从 72 家客户、1200 份合同、3000 条联系单，调整为 **24 家客户、168 份合同、313 条联系单**。三个业务员各 8 家；经理和老板仍可查看全部 24 家。

每个业务员的客户价值矩阵，默认本财年和本月范围内四个象限各 2 家客户；汇总身份每个象限各 6 家。主要客户使用简短、互不重复的“虚构·青禾”等名称。

象限仍由既有前端分析函数按实际回款、已确认利润和中位数计算。调整的是虚构订单单价、回款比例及虚构成本样例，图表规则、利润口径、汇率算法均未改动。历史业务、在制订单、批次、客户预存款、待计算利润和包装确认提醒仍有样例可演示。

精简数据生成器为 `local_api/demo_scenarios.py`，通过 `local_api/seed.py` 默认调用。旧的大规模生成器保留为 `build_large_seed`，只供回归和容量测试使用；不会再次把本地库或默认种子扩回 72 家。

本轮已先备份、再重建当前工作数据库。运行库及备份均在 Git 忽略范围内。没有更新公网体验站。

## 真实数据核查结论

替换前，以合同日期识别旧种子的生成基准为 2026-09-27，对工作库 18 类核心业务表逐字段、逐 ID 比对虚构生成器：没有新增、缺失或不同字段。范围包括客户、合同、联系单、批次、发货及表头/明细、到账/分配、发票/关联、成本、汇率、产品及规格、包装及版本、演示身份。

原有两份 SQLite 升级备份和一份旧 JSON 备份，也与同一虚构生成器一致。本轮重建前新备份保留了这套已经核对的旧虚构数据。辅助记录只有虚构分析预设和本地报表操作；没有业务修改历史或外部导入记录。

重建后，工作库**所有数据表的全部记录**再次与当天精简虚构生成器完整比对一致。SQLite 完整性检查为正常，外键错误为零。因此，本轮核查的当前工作数据库没有混入真实客户、公司或业务数据。

## 汇率

只保留按月份手动输入 USD/CNY、保存和删除的操作；页面名称为“手动汇率”。预置的 31 个月数值均是虚构计算样例，包含当前月份，来源统一为 `Manual`，没有行情服务请求、同步任务或自动同步接口。服务端拒绝其他来源，收款页面也明确使用手动维护的月度汇率。

验证覆盖实际 Edge 手动保存、SQLite 持久化及无外部资源请求。测试数值验证后已恢复为原虚构样例。
