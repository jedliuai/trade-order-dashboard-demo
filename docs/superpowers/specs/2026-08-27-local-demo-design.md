# 本地演示版设计

用户已授权自行决定架构，允许本地数据库和 Python worker；Telegram 测试密钥稍后提供。

## 目标与边界

保留现有 React 订单驾驶舱界面、业务编辑、经营分析、Excel/Word 导出和 Telegram 汇报。所有业务数据必须虚构，存放在项目目录内；不得访问原业务系统。移除 APS 同步、远程数据库、NAS、Cloudflare 和 n8n。生产日期字段改为手工维护的排产日期，不删除业务执行阶段。

## 架构

React/Vite 使用同源 `/api/` 调用本地 Python HTTP 服务，开发代理指向 `127.0.0.1:8765`。构建后的前端也可由 Python 直接提供。Python 使用标准库 SQLite，数据库为 `data/demo.sqlite3`，演示种子为 `data/demo-seed.json`。种子可重复生成，运行数据库不提交。SQLite 事务保护组合写入，原业务规则不主动改变。

前端现有数据缓存、业务接口尽量保留；旧 REST 调用改名为本地接口，Python 支持当前页面所需表查询及业务动作，不构造远程兼容服务或转发。空库自动从纯虚构种子初始化，重置需要明确确认并先备份当前库。

## 数据与角色

至少 60 个虚构客户、1000 份合同、2000 条联系单及关联批次、发货、回款、开票和成本，覆盖当前月和两年以上历史。展示多币种、多国家、多产品及未排产、生产中、待放行、部分发货、完成等状态。数据需有完整关联；利润只能由发票、成本和汇率计算，缺项显示待计算。

演示业务员、经理和老板身份用于本地展示汇报范围，不宣称具备生产级身份认证。只绑定环回地址，拒绝跨站写请求、未授权来源和任意路径访问。

## 导出与汇报

所有现有导出命令在本地执行，Excel 用 openpyxl、Word 用 python-docx，模板由代码生成通用标题和字段，绝不复用含真实信息的原始模板。保留日期/客户/发货/联系单筛选。

Telegram 提供状态、汇报预览、显式发送接口。Bot Token 与接收人 Chat ID 由本地环境文件配置，前端不可读取密钥。发送只到配置允许的接收人，默认未配置；不开机不运行、不依赖外部 worker、不实际发送测试消息直到用户提供凭据并要求联调。汇报按业务员、经理、老板的关系展示，使用与首页一致的经营指标。

## 安全与交付

清理旧 JSON、文档、截图、模板、测试里的真实标识与远程服务配置。旧 Git 历史不保留，新建私有 `jedliuai/trade-order-dashboard-demo`。只提交脱敏源码、虚构种子和说明。测试需覆盖持久化、关联一致性、事务回滚、业务写入、导出解包、Telegram 未配置和授权拒绝。运行现有可保留单元测试、lint、构建，并仅用 Edge 验收关键页面。
