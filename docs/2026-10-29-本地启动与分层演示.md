# 本地启动与分层演示

这轮只更新本地版，不发布 Cloudflare，也不把本机 SQLite 暴露到公网。

## 双击打开

在项目根目录双击 `启动本地演示.cmd`，脚本检查运行环境，必要时安装依赖、构建本地界面，然后启动服务并自动打开 Microsoft Edge。运行期间保留启动窗口，结束演示时按 Ctrl+C 或关闭该窗口。重复双击会复用正在运行的服务。

本机访问地址为 http://127.0.0.1:8765/。已有这台电脑的依赖时可以离线使用；首次安装依赖需要联网。缺少 Node.js 时脚本会提示安装 Node.js 22.12 或以上；首次安装后端还需要 Python 3.12 或以上。不会启动 Chrome。

脚本不会重置数据库。客户、合同和回款等编辑保存在 `data/demo.sqlite3`，关闭浏览器、重启服务后仍然保留。源码更新后重新启动窗口；脚本会在需要时重建前端。若端口被其他或旧服务占用，会明确提示，避免打开错误的程序。

## 如何演示三层权限

右上角“切换演示身份”切换当前角色。页面顶部“查看范围”切换下属汇总或个人业务，保持当前页面。切换查看范围不会获得被查看人的编辑权限。

| 身份 | 可查看 | 可编辑 |
| --- | --- | --- |
| 老板 · 顾远 | 全公司、东区、西区、四位业务员 | 不可编辑 |
| 东区负责人 · 许晴 | 东区汇总、林晓、陈晨 | 不可编辑 |
| 西区负责人 · 苏禾 | 西区汇总、周宁、沈安 | 不可编辑 |
| 东区业务员 · 林晓 / 陈晨 | 本人业务 | 本人的客户、合同、联系单、批次、发货与回款等 |
| 西区业务员 · 周宁 / 沈安 | 本人业务 | 本人的客户、合同、联系单、批次、发货与回款等 |

这些是纯虚构演示身份，可在同一台电脑切换，用来展示权限效果。它们不连接任何真实人员账号。

建议先用林晓展示本人 12 家客户和订单编辑，再切换东区负责人看 24 家客户的区域汇总，并选择单个业务员。最后切换老板，展示全公司 48 家客户以及东西两区和各业务员。经理和老板的编辑按钮置灰，详情、筛选、趋势和报表导出仍可使用。

客户及交易按负责人隔离，产品、包装、汇率是公共基础资料，业务员可维护，管理层只读。JSON 下载只包含当前查看范围；页面上的重置只恢复当前业务员自己的样例，执行前先在本机保存完整备份，其他人的记录与公共资料不会被重置。

## 客户与产品样例

四位业务员各 12 家客户，当前月和当前财年的回款—利润矩阵中，核心、潜力、规模、低贡献客户各 3 家。区域汇总每象限各 6 家，全公司汇总每象限各 12 家。分类沿用实际回款、开票、成本和利润的计算规则，没有人为存储气泡坐标或改动中位数规则。

保留 24 个旧虚构产品，再增加阿莫西林胶囊、头孢克肟胶囊、布洛芬片、扑热息痛片、注射用头孢曲松钠、注射用万古霉素、双氯灭痛注射液、氨甲环酸注射液、硫酸沙丁胺醇气雾剂，共 33 个产品、99 个规格。九种名称采用用户提供的通用名，规格及包装是演示样例，没有导入真实厂家的产品资料。所有客户、公司、订单、价格、数量和交易仍由本地生成器虚构创建。

每位业务员都有这九种产品的业务记录；不同月份会变换产品、规格和数量，产品经营、客户产品结构及趋势分析可以看到差异。种子共 336 份合同、625 张联系单、288 次发货与 288 笔到账，包含历史业务、进行中订单、预存款和一条缺成本待计算样例。

## 数据核对与验证

更新前，工作库全部记录与上一版 2026-10-28 虚构种子逐字段一致，未发现用户新增的真实业务记录。完整旧数据已备份到 Git 忽略的 `data/backups/`，再安装 2026-10-29 的新虚构样例。工作库和所有备份不进入 Git。

HTTP 回归覆盖区域隔离、老板下钻、管理层模拟业务员时仍不能写入、跨账号拒绝、授权范围导出、JSON 下载、经营指标和本人重置。跨语言测试使用实际订单计算四象限，覆盖月初、闰日及当前财年边界。Edge 实测角色切换、范围切换、编辑按钮、产品目录和本人编辑保存；保存结果直接从 SQLite 复查，验证后已还原测试记录。

金额、利润、回款、归档、预付款比例及汇率手动维护规则均沿用既定口径。
