# GitHub CI 跨平台锁文件修复

## 做了什么

修复了演示仓库第一次 GitHub Actions 检查在 Linux 上无法执行 `npm ci` 的问题。重新生成前端依赖锁文件，补齐 Linux 原生工具链所需的可选依赖，同时让锁文件中的项目名与前端 `package.json` 保持一致。

## 为什么做

本机 Windows 环境会跳过 Linux 专用的可选包，所以旧锁文件在本机安装和测试时看起来正常，但 GitHub 的 Ubuntu Runner 会检查到缺失依赖并直接停止。演示项目需要别人克隆后也能得到可重复的安装结果，不能只保证当前电脑可用。

## 值得记住的决策、坑和技术点

- 原生工具的可选依赖会因操作系统而异，Windows 上成功的 `npm ci` 不能替代 Linux 条件检查。
- 修复后同时验证 Linux 条件的依赖解析和 Windows 的真实全新安装，避免为了 CI 破坏本地开发。
- 依赖锁文件仍由 npm 正常生成，没有手工拼接包记录；生产依赖审计保持零漏洞。

## 一句话亮点

把“我的电脑能装”升级成“Windows 本机和 GitHub Linux CI 都能一键复现”的演示仓库。
