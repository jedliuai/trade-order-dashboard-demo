# README 展示升级与隐私复查

## 做了什么

把 README 改成了面向体验者的展示页：最前面放体验网址、共享账号和密码，配上品牌图标、彩色徽章和新绘制的蓝白横幅。用户提供的三段介绍只做轻微措辞和逻辑衔接，保留告别 Excel 重复填写、一次录入多次复用、随着积累看懂业务全局的核心表达。

用 Edge 从公网虚构演示站截取了五张图片：经营首页、客户价值矩阵、客户集中度、客户产品分析、合同管理。首页和价值矩阵直接展示，其余三张展开可看，避免首页一下拉得太长。GitHub About 的中文简介、体验网站和 14 个主题标签也补齐了。

额外复查了源码、测试、文档、种子和全部历史提交，清理了测试里的具体产品、公司名称和旧格式编号，把表单占位示例也改成 DEMO 编号。检查明细放在本轮公开资料隐私检查文档中，不重复记录原名称和私人信息。

## 为什么做

仓库已经公开，第一眼应该让外贸业务员或老板看懂用途，并且马上能进入体验。截图比堆功能名称更有印象；价值矩阵、贡献结构和合同进度也能把“从细节到全局”讲得更直观。

公开后的隐私检查不能只搜密钥，还要看产品名、公司名、业务编号和提交作者。用户明确要求不能带私人或真实业务信息，所以这次把检查范围补到了这些地方。

## 值得记住的决策、坑和技术点

只从本演示站截图，不使用旧业务素材。截图中保留“公网只读、全部虚构”的提示，PNG 也检查了附加元数据。体验密码是用户明确要求公开的共享入口，真实 Worker Secret 和 Telegram 配置仍不能提交。

README 的 HTML 混排要经过 GitHub 实际渲染，徽章和导航最好写在同一行，避免被插入换行。原有启动、数据位置、备份、导出和部署说明都保留，并用折叠区域减轻阅读负担。没有擅自添加许可证或更改财务规则。

替换示例时，需要同步保留搜索、排序等测试的意义；修改后 231 项前端测试、lint、构建都通过。README 经过 GitHub Markdown 渲染与 Edge 预览，所有图片加载正常，体验账号实际登录可用。

一个容易漏的地方是 Git 作者信息：旧提交还有真实姓名和私人邮箱，部分历史测试也有这次清理的名称。后续提交已经改用 GitHub 用户名和 noreply 邮箱；旧历史重写会影响提交号，已单独请用户确认，不能把这项待办写成已经完成。原材料只留本机忽略目录，没有发布。

## 一句话亮点

把公开仓库做成能看懂、能体验、有真实界面印象的产品展示页，再顺手把代码样例和提交身份里的隐私盲点找了出来。
