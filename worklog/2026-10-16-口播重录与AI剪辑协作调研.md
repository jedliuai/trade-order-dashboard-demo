# 这次把口播重录的配合方式想清楚了

## 做了什么

围绕个人订单驾驶舱的新一版口播视频，核对了 Claude Code 的本地文件工作方式、浏览器操作与录制能力、官方地区政策，并结合项目已有口播稿和分镜，整理了一份制作路线和可以直接复制的交接提示词。资料放在 docs，后面换助手也能继续用。

## 为什么做

一开始容易纠结：到底只给代码和网站，让 AI 自己录，还是自己全录好再交出去。更合适的顺序是先让 AI 看懂产品并列镜头表，再录口播和关键操作，最后补图形、关键词、辅助镜头和剪辑，避免录完才发现素材缺口。

## 值得记住的决策和坑

本地 Claude Code 不必绑定 GitHub，但本地运行也不代表内容不会传给模型服务。账号支持地区与资料最小授权是两回事，不能承诺只交代码就能消除账号风险。

官方浏览器集成支持 Edge，但交互 GIF 和正式录屏成片不同。自动录屏需要实际核对工具、分辨率与操作节奏，动画渲染器也可能启动浏览器，必须遵守本项目只用 Edge 的约束。

演示继续只用虚构数据：公网展示浏览和预览，本地版承担写入演示。利润、回款和状态规则不为镜头效果改口径。这次没有修改应用、启动浏览器、制作视频或绑定第三方账号，也没有把个人账号情况写进公开文档。

## 一句话亮点

把 AI 当成懂业务的导演搭档：先设计怎么讲清楚，再用真实演示和恰到好处的图形把它剪出来。
