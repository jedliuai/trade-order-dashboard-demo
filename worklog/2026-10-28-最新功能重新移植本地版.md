# 最新功能重新移植本地版

这次把原项目截至 2026 年 10 月 21 日的代码重新对照了一遍，移植到这个本地演示项目。参考提交是 `2edcc89`，最终仍使用 React 界面、Python 本地接口和 SQLite。原项目只参考源码，没有读取业务系统，也没有复制业务数据、模板、截图或历史文档。

## 做了什么

带回了累计预付款达标日、整笔收款与合同分配、客户预存款、新版收款台账、准备中发货整单编辑、发货作废复制、包装体积估算、包装版本车间和复制校验，以及窄屏导航、键盘标签页和图表改进。导出补齐放行申请、美金实际开票和预计开票，本地共支持十三类报表，发货安排可按批次或联系单汇总。

APS 同步按钮、自动跟踪开关、任务控制与远程数据访问都移除了。旧的排产日期字段名保留兼容，但只供手工维护。原先的外部物料查询链接也换成本地资料提示。

SQLite 升到结构版本 3。启动升级前用 SQLite Backup API 保存完整备份，回填分配生效日、版本车间，并给旧版单独发货补建一对一物理表头。原发货子记录、金额、发票和收款关联都保留。空库按启动当天生成虚构数据，旧库不会自动重置。

## 为什么做

原项目已经积累了不少新功能，旧演示版还停留在八月的交互和部分规则。用户希望得到尽量保持新版功能的本地版本，同时完全退出 APS 依赖。沿用已有本地服务比重新搭远程数据库更合适，也能保留已经编辑的虚构数据。

## 记住这些决策和坑

旧种子把 40% 预付款存成 40，新版使用 0–1 的比例，必须在备份后的迁移里转换成 0.4。这是单位转换，不是改成 30%；已有合同仍保持原约定，新表单才采用新版 30% 默认值。

收款分配不能简单全部沿用老水单日期。已有合同分配保留生效日期，后来增加的分配以当天生效；否则会把预付款达标日倒推到过去。合同还没有联系单金额时，即使比例为零也不要提前生成自动交期。

独立审查找出了三个真实缺口，全部补了先失败再通过的回归测试：零分配预存款也要进入收款导出；预计开票填写成本后需要公式；旧版单独发货必须能接上新版“作废并复制”流程。收款导出还专门区分本次合同筛选金额与整笔到账总额，避免重复计数。

放行申请中的车间使用联系单绑定的包装版本，不能随着模板改动漂移。APS 提供的制造周期等字段在本地留空手填。正式报表使用程序生成的通用版式，预计开票成本留空，计算公式不进入系统已确认利润。

Microsoft Edge 验证时，中途重新构建会让已打开页面引用旧的分包文件，刷新后再验证即可。没有启动 Chrome。验证了收款登记与删除、放行申请下载、390 像素窄屏菜单及 Escape 关闭；页面资源请求没有访问外部业务地址。

最终自动检查通过：2 项脚本测试、296 项前端测试、105 项 Python 测试，lint、TypeScript 和构建通过。数据库完整性检查正常、外键错误为零。与升级前快照逐项对比，1200 份合同、3000 条联系单、4888 条发货及其明细、2867 笔到账与分配、4237 张发票及关联的 ID 和数量/金额均保持一致。测试水单已经删除，运行库和备份不进入 Git。

本轮只交付本地版，不发布公网。既有公网演示仍保留十类静态报表示例，新增三类报表仅在本机即时生成。提交目标始终是演示仓库；同步前会保留远端新增的 README 内容和工作记录。
