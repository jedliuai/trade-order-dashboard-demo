# 本地占用盘点与清理脚本

## 做了什么

核对了项目的 GitHub 地址和远端 main，本地源码没有待提交内容，也没有领先或落后远端。逐项统计本地占用，整个项目约 970.15 MiB，其中 813.01 MiB 是可以重新安装或生成的依赖、构建、重复构建副本、Cloudflare 静态快照和验证缓存。

本次实际没有删除这些文件、没有释放磁盘空间：自动安全检查先后拦截了批量删除、指定目录删除和单独 node_modules 删除，只返回 blocked by policy，没有给出详细原因。没有改用其他删除工具绕过限制。

在 scripts/clean-local.ps1 保存了可供本机执行的清理脚本。默认只显示清单，只有显式加上 -Apply 才清理；白名单对应本次已经核对的产物，不泛化删除其他文件夹。实际运行了 Windows PowerShell 的默认预览，并核对了 291 个原有源码、素材和数据文件的 SHA-256，文件保持完整。删除模式受环境限制未执行，不能写成已通过实际删除验证。

## 为什么做

用户希望删掉不用的本地文件，减少电脑占用，但 GitHub 并不是本地所有东西的备份。源码已经同步，封面图片、SQLite 和数据备份仍在 Git 忽略目录；把它们当缓存删除会丢掉素材和本地修改。

用户明确选择保留封面、数据库和数据备份，只清理可重建文件。以前隐私检查留下的原材料、Git bundle 和审计资料也先保留，不为了清理把它们发布到公开仓库。

## 值得记住的决策、坑和技术点

依赖约占 346 MiB，多份前端构建和生成快照又占了约 463 MiB。清理脚本先检查所有路径都在本项目内、目录和祖先不是链接、目标不含版本文件且受 Git 忽略，再检查项目服务是否仍在运行。真正删除前记录其他文件的校验值，删除后逐一核对。脚本使用 UTF-8 BOM，兼容 Windows PowerShell 读取中文。

清理后要重新运行 npm run setup 才能开发；使用构建模式还需 npm run build，Cloudflare 的根目录依赖要另用 npm ci 恢复。源码、锁文件和虚构种子保留，因此依赖和静态快照可重新生成，不需要上传它们。

还有一个容易误判的点：项目在 D 盘，D 盘本次还有约 195 GiB 可用，真正紧张的是 C 盘，只剩约 0.8 GiB。即便清理完成，也主要释放 D 盘空间；本轮没有扩展到其他项目或 C 盘。

## 一句话亮点

给订单驾驶舱找出了八百多兆可重建文件，把真正需要保留的素材和数据先守住，清理清单也变成了可复用的脚本。
